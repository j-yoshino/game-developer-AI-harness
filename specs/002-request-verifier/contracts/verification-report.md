# Contract: 検査の報告

確かめる者が、メインに返す報告の形式。日本語で書く。メインは、全文を、納品書の末尾の「確かめる者の報告」の節に、そのまま追記する。

## 形式

```markdown
## 確かめる者の報告

判定: 承認可 / 要修正 / 判定不能

### 完了の判定との照合
- <完了の判定の項目>: 満たす / 満たさない / 判定不能 — 根拠: <path:line またはコマンド出力>

### 確認していないことの抜け
- <完了の判定の項目>: <その項目の主張を、確認方法が捕まえていない点>
  (なければ「なし」)

### 補足
- <完了の判定に直結しない一般的な懸念。なければ「なし」>

### 再実行の結果
- `<コマンド>`: <結果(成功・失敗と、要点)>
  (再実行できるコマンドがなければ「なし」。最大3つ)

### レビューの指摘
- <レビューしたエージェントの名前>: <CRITICAL と HIGH の指摘を、そのまま。なければ「なし」>
- <対象外の拡張子があれば>: 対象外

### 確かめる者が確認していないこと
- <この検査では捕まえられないもの。空欄不可。なければ「なし」>
```

## 規則

| 規則 | 内容 |
|---|---|
| 判定 | 承認可 / 要修正 / 判定不能 のいずれか1つ。指摘が無ければ「承認可」。指摘を作り出さない |
| 要修正の条件 | 完了の判定を「満たさない」項目がある、確認していないことの抜けがある、再実行が失敗した、レビューの CRITICAL または HIGH の指摘がある、のいずれか |
| 判定不能の条件 | 根拠を得られず、満たすとも満たさないとも言えない項目がある(例: 実行環境がない) |
| スタイルの指摘 | 書かない |
| 長さ | 150 行以内を目安。CRITICAL と HIGH はそのまま残し、それ以外は要約する |
| 書き換え | 検査役は、ファイルを書き換えない。報告の「確かめる者が確認していないこと」に、書き換えの有無を確認していない旨を書く |
