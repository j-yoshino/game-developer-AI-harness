# Data Model: 確かめる者

spec の Key Entities を、フィールドと規則に展開する。データベースはなく、すべてファイル上の書式である。

## 検査の対象の判定(Verification Trigger)

| 依頼の層 | 検査 |
|---|---|
| 本件 | 必ず通す |
| 軽作業 | 作業の差分に、ソースファイルまたはテストファイルが含まれるときだけ通す |

- ソースファイル: 拡張子が `.cpp` `.hpp` `.cc` `.hh` `.cxx` `.h` `.cs` `.rs`。
- テストファイル: `tests/` または `Tests/` 配下、またはファイル名に `Test` または `_test` を含むもの。
- ドキュメント、rules、設定、HTML だけの変更は、対象外。納品書に「検査不要: <理由>」を1行書く。
- 迷ったら、検査する側に倒す。

## 納品書(拡張)

既存の納品書(spec 001 の `contracts/delivery-note.md`)に、次を足す。

| 項目 | 規則 |
|---|---|
| 「確認した方法」 | コマンドと出力(要点)を書く。コマンドを持たない確認(目視など)は、その旨を書く |
| 末尾の「確かめる者の報告」の節 | 検査を通したとき: 報告の全文をそのまま。通さないとき: 「検査不要: <理由>」の1行 |

## 検査の報告(Verification Report)

確かめる者が返す。形式は contracts/verification-report.md。

| 欄 | 規則 |
|---|---|
| 判定 | 承認可 / 要修正 / 判定不能 |
| 完了の判定との照合 | 項目ごとに、満たす / 満たさない / 判定不能と、根拠(`path:line` またはコマンド出力) |
| 確認していないことの抜け | 完了の判定に直結する抜けだけ。なければ「なし」。一般的な懸念は「補足」に書く |
| 再実行の結果 | 最大3つ。コマンドと結果 |
| レビューの指摘 | CRITICAL と HIGH を、そのまま。対象外の拡張子は「対象外」と書く |
| 確かめる者が確認していないこと | 空欄不可。なければ「なし」。検査役が書き換えをしていないかの確認は、していない旨を書く |

### 判定の意味と、差し戻し
- 承認可: 納品書は「確認待ち」のまま、ユーザーの承認を待つ。
- 要修正: 作る者が直し、納品書を更新し、検査を呼び直す。最大2回。3回目にも要修正なら、未解決の指摘を載せたまま「確認待ち」で報告する。
- 判定不能: 差し戻しに数えない。そのまま報告する。

### 状態の遷移
- 検査の呼び出し回数: 0 → 1 → 2 → 3(3回目で打ち切り)。判定不能は、回数に数えない。
