# Contract: 納品書

`docs/納品書/` に置く Markdown。テンプレートは `docs/納品書/_template.md`。日本語で書く。

## ファイル名

| 種別 | 名前 |
|---|---|
| 新規実装 | `<NNN-feature>.md`(`specs/<NNN-feature>/` と揃える) |
| 軽作業 | `<YYYY-MM-DD>-<題名>.md` |

## 書式

```markdown
# 納品書: <題名>

- 状態: 確認待ち
- 依頼: <新規実装: spec へのリンク / 軽作業: 「こう理解した」と「やらないこと」>
- 納品日: <YYYY-MM-DD>

## 完了の判定ごとの報告

### <完了の判定の1項目>

- 何をしたか: <実際に行ったこと>
- 確認した方法: <手順。「確認した」だけは不可>
- 確認していないこと: <その方法では捕まえられないもの。なければ「なし」>

## 追加した項目

<依頼に無い作業を足したときだけ書く。なければ「なし」>
```

## 規則

| 規則 | 内容 |
|---|---|
| 行の対応 | 依頼票の「完了の判定」の各項目に、1つの節を置く。軽作業は、聞き取りで確認した「こう理解した」と「やらないこと」の各項目に置く |
| 確認していないこと | 空欄不可。なければ「なし」と書く。空欄は「全部確かめた」という主張になる |
| 確認した方法 | 手順を書く。結論と方法を、同じ場所に書く |
| 追加した項目 | 依頼に無い作業を足したときは、黙ってサービスせず、申告する |
| 状態 | 置いた時点で「確認待ち」。承認はユーザーが行い、「承認済み」に変える |
| 完了の言い方 | 「確認待ち」の間は、完了とは言わない |

## 第1版の限界

納品書は、作った者(メインの会話)が書く。「確認していないこと」は自己申告である。独立した確認は、「確かめる者」の別の設計で扱う。
