# Contract: 依頼票(spec の先頭の節)

`.specify/templates/overrides/spec-template.md` が、新しい spec の先頭に出す節。この spec 自身(`spec.md`)の「依頼票」の節が、実例である。

## 書式

```markdown
## 依頼票

### ご要望(原文)

- 「<ユーザーの言葉をそのまま引用する>」

### こう理解した

<言い換え。原文と並べる>

### 誰のためか

<誰が読む・使う・判断するか>

### やらないこと

- <範囲外・できないこと>

### 完了の判定

- [ ] <納品書の各行に対応する項目>
```

## 規則

| 欄 | 規則 |
|---|---|
| ご要望(原文) | 引用符付きで、原文のまま。要約・言い換えを含めない |
| こう理解した | 原文の下に置く。ユーザーが、ここだけ読んで誤解に気づける長さにする |
| 誰のためか | 要望の文面に現れない場合でも、必ず聞いて埋める |
| やらないこと | 着手前に確定する。作業後に足さない |
| 完了の判定 | チェックボックス。検収基準。各行は、納品書の1行に対応する |

## 埋まらなかった欄の扱い

窓口は、埋まらなかった欄だけを、`AskUserQuestion` で、選択肢の形で聞く。自由記述で聞いてよいのは、ユーザーだけが持つ事実(番号、場所など)に限る。

## 確定

ユーザーが、「伺いたい点」に答え、「やらないこと」と「完了の判定」に合意した時点で確定する。確定するまで、作業(plan 以降)に入らない。
