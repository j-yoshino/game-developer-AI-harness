# Tasks: 相談役(ゲーム制作の第三者)

**Input**: Design documents from `/specs/003-game-advisor/`

**Prerequisites**: plan.md、spec.md、research.md、data-model.md、contracts/(delegation-message.md、advisor-report.md、added-points-record.md)、quickstart.md

**Tests**: 自動テストは作らない(plan.md の Testing)。代わりに、機械的に確かめられるもの(ファイルの存在、frontmatter、出典の書式、桜井さんの個別ソースがないこと、全文の転記がないこと)は、タスクの中でコマンドで確かめる。**新しいセッションが要る検証は、ユーザーの手が必要**で、`(ユーザー)` と付けた。

**Organization**: タスクはユーザーストーリーごとにまとめた。

## Format: `[ID] [P?] [Story] Description`

- **[P]**: 並行して進められる(別のファイルで、未完了のタスクに依存しない)
- **[Story]**: US1(抽象的な依頼に解釈案を提案し、合意を取る)、US2(補った点の記録と、検収での取り消し)、US3(8つの見方と根拠)、US4(軽作業でも呼ぶ)、US5(呼ばない場合と、ユーザーが呼ぶ場合)

## 共通の注意

- `.claude/agents/*.md` と `.claude/rules/window.md` は、英語で書く。相談役の返答の言語だけ、日本語にする(形式は contracts/advisor-report.md)。日本語を含めてよいのは、`docs/ゲーム制作` や `docs/納品書` のパスと、返答の形式の例(日本語の見出し)だけ。
- `window.md` を編集したら、同じ変更で `docs/rules-ja/window.md` の日本語訳も更新する。
- `window.md`・`window-verifier.md`・`spec-template.md`・`納品書/_template.md` は、複数のストーリーが同じファイルに追記する。同じファイルを編集するタスクは、順に行う([P] を付けない)。
- **著作物**: 任天堂の記事は、出典付きの要約のみ。引用は 1 記事から 1 か所、15 語未満。全文を転記しない。記事は、`https://www.nintendo.co.jp/jobs/keyword/<番号>.html` から、1 本ずつ取得する(静的ページ)。
- **桜井さんの二次資料**: 個別のソース(動画の番号、リポジトリ名、まとめ記事の名前)を、知識のファイルにも、相談役の指示にも書かない。内容は、自分の言葉で整理する。二次資料の本文は、リポジトリに入れない。
- 相談役の `tools` に、`Edit`・`Write`・`Bash`・`Agent` を含めない。
- `vendor/` 配下は編集しない。
