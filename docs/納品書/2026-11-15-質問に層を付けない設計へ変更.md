## 完了の判定ごとの報告

### こう理解した: 質問(作業を求めない発言)には層を判定せず、`window-question` が呼ばれる想定にする。窓口が判定するのは、作業の依頼(軽作業・本件)だけ

- 何をしたか: 次を変えた。
  - `.claude/rules/window.md` と `docs/rules-ja/window.md`: 層の表から質問の行を消し、質問は `window-question` が答え層は判定しない、と書いた。
  - `.claude/hooks/window-reminder.sh`: 注入文を、質問には `window-question` を呼び層を判定しない、作業の依頼は軽作業・本件に判定する、に変えた(366 文字)。
  - `.claude/skills/window-question/SKILL.md`: 「質問と判定されたとき」という前提を、「作業を求めない発言のとき」に変えた。
  - `AGENTS.md`、設計書、spec、plan、data-model、research、quickstart、contracts/hook-io、tasks(変更の記録を追加)、実装フローの HTML(質問の流れから「質問と判定する」の手順を削除)。
- 確認した方法: フックのスクリプトにサンプル JSON を流し、妥当な JSON で、注入文が 366 文字(上限 400)であることを確認した。`window.md` は 52 行で、日本語は `docs/納品書` のパス以外にないこと、frontmatter がないこと、訳と見出し数(8)・箇条書きと表の行数(21)が一致することを確認した。HTML のタグの対応をスクリプトで確認し、ブラウザーで、手順の数(質問 2・軽作業 4・本件 9)と、質問の行が「質問(層は判定しない)」であること、見取り図の質問の表が 2 行であることを確認した。「質問と判定」「質問・軽作業・本件」の文字が、残っていないことを `grep` で確認した(設計書の検証の例1か所は、入力する例の列挙で、残して問題ない)。
- 確認していないこと: 質問に層を付けない設計で、実際に `window-question` が呼ばれるか。呼ばれる前提は、`window.md` とフックの注入文で指示しているだけで、遵守は保証されない(新しいセッションの検証 T010 が必要)。質問と作業の依頼が混ざった発言の挙動。
