## 完了の判定ごとの報告

### 1. 窓口の表の列名を「呼び出すスキル」にし、スキル名で書く

- 何をしたか: `docs/実装フロー/実装フロー.html` の窓口の表の列名を「進む先」から「呼び出すスキル」に変え、各行をスキル名で書いた(質問: `window-question`。軽作業: `superpowers:brainstorming` → `systematic-debugging`、`test-driven-development`、`verification-before-completion`。本件: `superpowers:brainstorming` → `/speckit-specify` → 以降は本件の流れ)。
- 確認した方法: ブラウザーで開き、JavaScript で、窓口の表の見出しが「層|条件|呼び出すスキル」であること、「進む先」の文字が HTML に 0 件であることを確認した。
- 確認していないこと: 各セルの書き方が、あなたの意図に合っているか。

### 2. 「スキルの呼び出し(原則)」の節を削除する

- 何をしたか: 前回足した、「スキルの呼び出し(原則)」の節を削除した。スキル名を明記するのは、窓口の最初の分岐の表だけになった。
- 確認した方法: HTML に「スキルの呼び出し」の文字が 0 件であること、見出しの一覧から消えていることを確認した。
- 確認していないこと: 削除に伴い、`window-question` と `check-claude-docs` がこのリポジトリ独自のスキルであることを示す一覧も消えた。窓口の表には `window-question` が載るが、`check-claude-docs` は、実装フローのどこにも載らなくなった。

### 3. 「機能1つの流れ」と「フロー全体の見取り図」を、質問・軽作業・本件に分ける

- 何をしたか: 「機能1つの流れ」を、「1. 質問の流れ」(3手順)、「2. 軽作業の流れ」(4手順)、「3. 本件(新規実装)の流れ」(既存の9手順)に分けた。「フロー全体の見取り図」も、層ごとの3つの表に分けた。見出しの番号を 0〜6 に振り直した。
- 確認した方法: HTML のタグの対応をスクリプトで確認した。ブラウザーで開き、`<h2>` が 8 個、手順の数が各流れで 3・4・9 であること、見取り図の表が3つで、いずれも見出しが「段階|呼び出すスキル|成果物」であることを確認した。外部への参照(`http`)が 0 件であることを確認した。
- 確認していないこと: 質問と軽作業の手順の内容が、`.claude/rules/window.md` の経路と、細部まで一致しているか(一致するように書いたが、1行ずつ突き合わせてはいない)。見た目(余白や配色)を、人の目で確かめてはいない。

## 追加した項目

- 本件の手順の項目名「使うもの」を、「呼び出すスキル」に統一した(依頼は表の列名だけだったが、同じ文書内で言い方がそろわなくなるため)。
