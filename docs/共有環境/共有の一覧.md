# 共有の一覧(Claude → Codex・Antigravity CLI)

作成日: 2026-11-15。仕様: `specs/004-cross-tool-claude-env/`。

- 正本は `.claude/`。`.agents/` と `.codex/` は、`python scripts/sync-agent-env.py` で生成する(手で直さない)。正本とのずれは、`python scripts/sync-agent-env.py --check` で検査する。
- 状態は `共有` / `一部` / `不可`。`一部`・`不可` には、理由と出典を付ける。
- 「確認」の `自動検査` は、このリポジトリで、コマンドで確かめたこと。`ユーザー検収` は、実際の Codex・Antigravity で、ユーザーが確かめること(このマシンには、`codex` と `agy` がない)。

## 同期で変わったこと(既存の `.agents/`)

- ECC が入れた `.agents/rules/` の 15 件(`cpp-*`、`csharp-*`、`rust-*`)は、生成物で置き換えた。元のファイルは `paths:` だけで `trigger:` がなく、Antigravity の公式の仕様では、`trigger` のない rules は黙って捨てられる(推論。実機では未確認)。
- ECC が入れたスキル 6 件とエージェント 5 件は、`.claude/` と内容が一致していたため、差分は出ていない。
- `.agents/ecc-install-state.json` の記録は、この置き換えで古くなった。ECC の更新・削除が、この状態で動くかは、未検証。
- `.agents/workflows/`(6 件)と `.claude/commands/` は、対象外。そのまま。

## 確認できていないこと

- Antigravity が、Claude 形式のエージェント(`tools`、`model` を含む frontmatter)を受け付けるか。
- 両ツールのフックが、Windows で動くか。Codex の `commandWindows` の動作。
- Codex が、`.codex/agents/*.toml` を名前で呼べるか。
- Antigravity の `PreInvocation` が、ユーザーのプロンプトごとに 1 回なのか、モデル呼び出しごとなのか。
- 直下の `.claude-plugin/plugin.json` を足したことの影響: `claude plugin validate .` は通り、4 つのプラグインは有効のまま。ただし、`plugin.json` に `author` がない警告と、リポジトリのルートの `CLAUDE.md` がプラグインのコンテキストとして読まれない旨の警告が出る(エラーではない)。
