# 変換ブランチ(`develop` → `main-build` → `main`)

作成日: 2026-11-17。仕様: `specs/006-plugin-conversion-branch/`。

`develop` で作業し、`main` に出す最小の構成を、スクリプトで組み立てる。結果は、ローカルの変換ブランチ(`main-build`)にコミットする。`main` への PR・マージと push は、外向きの操作なので、このスクリプトに含めない(ユーザーの確認のもとで、別に行う)。

## 流れ

```text
develop(ツールごとに独立した正本: .claude/、.codex/、.agents/)
   ↓ python scripts/build-main.py --out <出力先>             (組み立て。同じ入力で、同じ出力)
   ↓ python scripts/publish-main-branch.py                    (ローカルの main-build ブランチにコミット。push しない)
main-build(組み立てた構成だけを持つ。手で直さない)
   ↓ PR(ユーザーの確認のもとで、手で)
main
```

## 手順

1. `develop` の変更を、コミットする(`publish-main-branch.py` は、追跡済みのファイルに、未コミットの変更があると、拒否する。試験の実行は `--allow-dirty`)。
2. 組み立てだけ確かめるとき: `python scripts/build-main.py --out <リポジトリの外のフォルダ>`。`--check` を付けると、出力先と、新しい組み立ての差を確かめる(書かない)。
3. ローカルのブランチにコミットするとき: `python scripts/publish-main-branch.py`(ブランチ名は `--branch` で変えられる。`main`・`develop`・`master` には、書かない)。
4. 変更がなければ、コミットしない。変更があれば、`build: develop <短いハッシュ> から main の構成を組み立てる` というコミットを、1 つ足す。履歴は、最初の実行で、空の状態(orphan)から始まる。

## `main` に置くもの

- `.claude/`(`settings.local.json` を除く。`settings.json` を、テンプレートから出力: 窓口のフックの登録と、外部プラグインのマーケットプレイス・有効化。個人の設定は入れない)、`.codex/`、`.agents/`(`plugins/marketplace.json` は、外部プラグインを Git の URL で指す `main` 用に置き換える)。
- `.claude-plugin/marketplace.json` と、`vendor/unreal-engine-skills-for-claude-code-plugin`(submodule。コミットでは、gitlink)、Unreal だけの `.gitmodules`。
- `AGENTS.md`(`main` 専用の最小版: rules の案内)、`CLAUDE.md`(`@AGENTS.md`)、`README.md`(導入の手順)、`.gitattributes`。

## `main` に置かないもの

`specs/`、`docs/`、`scripts/`、`.specify/`、`vendor/` の superpowers・Unity・i-have-adhd、`.claude/settings.local.json`、`.gitignore`、追跡されていないファイル(`.claude/ecc/`、`.agents/ecc-install-state.json`、`.agents/plugins/superpowers/`)。

組み立ては、`git ls-files`(追跡済みのファイル)を元にし、許可リストに当たるものだけを出す。出力に、このマシンの絶対パスや、個人の設定が入ると、組み立てを失敗にする。

## テンプレート

`scripts/templates/`: `main-AGENTS.md`、`main-CLAUDE.md`、`main-claude-settings.json`、`main-codex-marketplace.json`、`main-README.md`。`main` の中身を変えたいときは、ここを直して、組み立て直す。

## 制約・確かめていないこと

- ツールごとの正本は独立していて、同じ内容(例: `window-question`)が、複数の場所にある。ずれを検知する仕組みはない。
- 外部プラグインの別導入(`README.md` の手順)は、Claude の `.claude/settings.json` の新しい動作(信頼ダイアログの後、プロジェクト単位)と、Codex の Git の URL を指すマーケットプレイス、Unity・i-have-adhd・Antigravity の導入を、実機では確かめていない。
- `directory` の `path: "."` の基準(公式に記載なし。`develop` では動いている)。
- Unreal が、公式マーケットプレイス(`claude-plugins-official`)にあるか(手元のキャッシュ(2025-12)には、載っていない。未確認)。
- 試験で使った `main-build-test` ブランチは、試験の後、削除する(ユーザーの確認が要る)。
