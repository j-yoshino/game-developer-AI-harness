# 4. 迷わなさ

## 見方の説明

初めて遊ぶ人が、説明を読み込まなくても、今何をすればよいかが分かるか。これを問う見方である。作った側は仕様を知っているので、初見の人の反応が分からなくなりやすい。依頼や仕様を読むときは、最初の数分に何が起きるか、どこで迷う可能性があるか、それを誰が確かめるかを見る。

## 相談役が投げる問い

- 初めて遊ぶ人は、起動してから最初の操作をするまでに、何を見て何を読むか。
- 遊び方は、説明の画面で伝えるのか、遊んでいる流れの中で伝えるのか。
- ゲームにあまり慣れていない人は、想定する遊ぶ人に入っているか。入るなら、その人に触らせる機会はあるか。
- 画面上の言葉や記号は、ゲームに触れたことのない人にも通じるか。ボタンの位置や構え方は、見て分かるか。
- 遊ぶ人が詰まる場所は、どこだと予想しているか。実際に詰まったとき、どう気づくか。
- すべてを説明するか、遊びながら見つけてもらう部分を残すか。残すなら、どの部分か。

## 根拠

### 任天堂の記事(出典つき)

- **記事 112「遊ばれ方をイメージしながらデザイン」** — https://www.nintendo.co.jp/jobs/keyword/112.html(職種: 記載なし。本文ではUI/UXデザイナーの語り。強さ: 強)
  - 要約: ゲームを触ったことのない人も想定して、画面上の「1P」「2P」のような表示を避け、手元のコントローラーの色や左右を画面に出して対応づけた。普段あまり遊ばない人に試作を触ってもらうと、ボタンの位置や構え方が文字だけでは伝わらないと分かり、拡大表示などで改善した。説明は必要な場面にだけ出し、影響の小さい技術はあえて説明を減らしたとされる。
- **記事 173「実体験をもとに操作を磨きこむ」** — https://www.nintendo.co.jp/jobs/keyword/173.html(職種: 記載なし。本文ではプログラマーの語り。強さ: 中)
  - 要約: 開発の終盤で、はじめて遊ぶ人にも操作が直感的に伝わるかを特に意識した。社外の人、子ども、普段あまり遊ばない人にも触ってもらい、操作中の様子を観察して磨いた。主題は操作の表現であり、迷わなさだけを扱う記事ではない。
- **記事 163「レースの世界で立ち止まる楽しさ」** — https://www.nintendo.co.jp/jobs/keyword/163.html(職種: 記載なし。本文ではプランナーの語り。強さ: 中)
  - 要約: 撮影機能のUIで、言葉の選び方やボタンの位置と順番を考え続けた。機能を詰め込みすぎて触るのが難しく見えたことがあり、使ってもらえなければ意味がないと、機能を削り足しして文言も直した。単一機能のUIの話で、ゲーム全体の入口の話ではない。
- **記事 065「覚悟を決めて手を挙げる」** — https://www.nintendo.co.jp/jobs/keyword/65.html(職種: 記載なし。本文では地形デザイナーの語り。強さ: 弱)
  - 要約: 新しいコントローラーを使うゲームの冒頭コースで、操作の説明に必要な情報を伝えつつ、地形が遊びの邪魔にならないよう、何度も作り替えた。必要な距離を考え、自分で走って感触を確かめた。迷わせない工夫の記述は短く、主題は地形デザインである。

### 二次資料の複合結果(出典なし)

- 遊び方の説明は、長い文章や何もない練習の場で行うより、本編の流れの中で、遊びながら学べる形にするのがよいとされる。操作が複雑なほど、理解させる仕組みを最初の企画から入れておくべきだとされる。(強)
- 導入は、説明や前置きを後回しにして、早く遊びの見せ場を見せる方がよいとされる。「最初の数分」のような目安が挙がるが、条件により変わり、具体的な時間は根拠が弱い。(中)
- メニューの項目には説明文をつけ、項目名と同じ言葉の繰り返しや専門用語を避けるとされる。例として、「シングルモード」より「ひとりで遊ぶ」のような言い換えが挙がっている。(中)
- 子どもや初めて触れる人に遊ばせ、話を聞くより反応を観察する方がよいとされる。どこで詰まり、どこで飽きるかが見える。(中)
- 初めての人に向けて入口の敷居を意識して下げる、という考え方がある。ただし、遊ぶ人が本気を求めているときの手加減は失礼になる、という但し書きも付く。(弱)
- 分かりやすさと、見た目のスタイルは、相反しやすいとされる。どちらを優先するかは、ゲームの目的や世界観によって変わる。(中)
- 遊ぶ人の腕前の幅が広いゲームでは、トップメニューからボタンを押し続けるだけで本編に入れるように設計しておく、という例が挙がっている。(弱。特定の作品の例)

## 失敗の兆候

- 仕様に「直感的に遊べる」とあるだけで、誰が・どこで確かめるかが書かれていない。
- 遊び方が、長い説明画面や、本編と切り離された練習場に集められている。
- 初めて遊ぶ人に触らせる機会が計画にない。確かめるのが、開発者自身に限られている。
- 画面の言葉やボタンの指示が、ゲームに慣れた人しか分からない言葉で書かれている。
- 機能を足し続けて、最初の画面に出る情報が増える一方になっている。

## この見方の限界

- 任天堂の記事は、語り手の体験談である。迷わなさがどれだけ売れ行きや満足度に効いたかは、記事からは分からない。
- 記事は、大人数のコントローラー体験や大作のUIに偏っている。専用のコントローラーがない環境、個人制作、画面の少ない小さなゲームについては、記事から言えることは少ない。
- 記事 065 は、この見方の根拠としては弱い。迷わせない工夫は、地形デザインの話の一部にとどまる。
- 二次資料の複合結果は、一部が対戦アクション寄りで、遊ぶ人が長く遊び続ける前提で語られている。短時間で遊び終えるゲームや、想定する遊ぶ人が熟練者に限られるゲームには、そのまま当てはまらない。
- 資料の原則どうしの食い違いがある。すべてを説明せず、遊びの中で発見してもらう考え方と、「迷わせない」考え方は、並べると緊張する。どこまで説明し、どこから任せるかは、ゲームの性格によって変わり、資料からは決まらない。分かりやすさとスタイルが相反する、という指摘も同じ種類の食い違いである。
