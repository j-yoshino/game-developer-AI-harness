## ファイルの構成

- `観点/` — 見方ごとの、説明・投げる問い・根拠・失敗の兆候・限界。相談役は、最初に、これと README を読む。
- `出典.md` — 任天堂の記事の番号、題名、URL、職種、取得日、使った見方。
- `観点の検証メモ.md` — 見方を決めるときの、記事 139 本の通読の記録。相談役は読まない(量が多く、出典.md と重なるため)。

## 書き方の規則

- **任天堂の記事**は、出典付きの要約。記事の番号・題名・URL を書く。全文を転記しない。引用は 1 記事から 1 か所、短く。記事は、インタビュー当時の情報で、1 社の採用向けの体験談である。
- **二次資料**(非公式の要約)は、「二次資料の複合結果」と書く。個別のソースは書かない。動画本体とは照合していない二次情報である。
- 根拠には、強さの印(強・中・弱)を付ける。強さは、根拠の厚さで、発言の正しさではない。
- 断定的な数値や「必ず」の言い方は、そのまま採らず、条件つきで書く。
- 資料の例は、対戦アクション、大作、大規模なチームに偏る。ジャンルや規模が違えば、狙い(遊ぶ人を楽しませること)から読み替える。
- 資料の原則どうしが食い違うときは、両方を書く。
