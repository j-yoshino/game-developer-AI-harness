# C++ コーディングスタイル

> このファイルは [common/coding-style.md](../common/coding-style.md) を C++ 固有の内容で拡張します。

## モダン C++(C++17/20/23)

- C スタイルの構文より、**モダンな C++ の機能**を優先する
- 型が文脈から明らかなときは `auto` を使う
- コンパイル時定数には `constexpr` を使う
- 構造化束縛を使う: `auto [key, value] = map_entry;`

## リソース管理

- **どこでも RAII** — 手動の `new` / `delete` は使わない
- 排他的な所有には `std::unique_ptr` を使う
- `std::shared_ptr` は、共有所有が本当に必要なときだけ使う
- 生の `new` より `std::make_unique` / `std::make_shared` を使う

## 命名規則

- 型/クラス: `PascalCase`
- 関数/メソッド: `snake_case` または `camelCase`(プロジェクトの規約に従う)
- 定数: `kPascalCase` または `UPPER_SNAKE_CASE`
- 名前空間: `lowercase`
- メンバー変数: `snake_case_`(末尾にアンダースコア)または `m_` 接頭辞

## フォーマット

- **clang-format** を使う — スタイルの議論はしない
- コミット前に `clang-format -i <file>` を実行する

## 参照

C++ コーディング標準とガイドラインの包括的な内容は、スキル `cpp-coding-standards` を参照してください。

## プロジェクト規約: C++ Core Guidelines

出典: https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines(2026-11-15 に全文を読了。以下の ID は原典のルール ID)。この節は、上の汎用的な ECC の記述より優先します。`Source/` 配下の Unreal Engine のコードでは、`.claude/rules/unreal-engine/coding-style.md` がこの節より優先します。

### 哲学とインターフェース(P、I)
- P.1〜P.3: 意図をコードで表す、ISO 標準 C++ で書く、名前・型・アルゴリズムで意図を示す。P.4〜P.7: 静的な型安全、実行時チェックよりコンパイル時チェック、実行時エラーは早く検出する。P.8〜P.9: リークと無駄をなくす。P.10: 不変データを優先する。P.11: 雑な低レベルコードをカプセル化する。P.12〜P.13: 解析ツールと良いライブラリを使う。
- I.1〜I.4: 明示的で強く型付けされたインターフェース、非 const のグローバルを使わない(I.2)、シングルトンを避ける(I.3)。I.5〜I.8: 事前条件・事後条件を明記する(`Expects()` / `Ensures()`)。I.9: テンプレート引数をコンセプトで制約する。I.10: 失敗は例外で知らせる。I.11〜I.13: 生ポインターや参照で所有権を渡さない、null でないポインターには `not_null`、配列は `span` で渡す。I.22: グローバルの複雑な初期化を避ける。I.23〜I.24: 引数は少なく、同じ型の引数を隣り合わせにしない。I.25〜I.27、I.30: 抽象クラスによるインターフェース、ABI のために C スタイルのサブセットか Pimpl、規約違反は実装の内側に閉じ込める。

### 関数(F)
- F.1〜F.3: 意味のある操作に名前を付ける、関数は論理的な操作を1つだけ行う、短く保つ。F.4〜F.6: コンパイル時評価が必要なら `constexpr`、`inline` は小さくて時間的に厳しい関数だけ、投げない関数には `noexcept`。F.7: 所有権が重要でない限り、スマートポインターではなく `T*` / `T&` を受け取る。F.8〜F.11: 純粋関数を優先、使わない引数は名前を付けない、再利用できる操作には名前を付ける、1箇所だけの操作には無名ラムダ。
- 引数 F.15〜F.21: 安価にコピーできる「入力」は値渡し、それ以外は `const&`、「入出力」は非 const の `&`、「ムーブ元になる」は `X&&` と `std::move`、「転送」は `TP&&` と `std::forward`、出力引数より戻り値、複数の出力は名前付き構造体で返す。F.60: 「引数なし」が有効なら `T*`、そうでなければ `T&`。F.22〜F.27: 単一オブジェクトは `T*` / `owner<T*>`、`not_null<T>`、`span<T>`、`zstring`、所有権の移転は `unique_ptr`、共有は `shared_ptr`。
- 戻り値 F.42〜F.49: `T*` は位置を示すためだけで所有権には使わない、ローカルへのポインターや参照を返さない(F.43)、`T&&`・`std::move(local)`・`const T` を返さない、`main` は `int` を返す、代入は `T&` を返す。F.50〜F.56: 関数で足りないときにラムダ、オーバーロードより既定引数、ローカルで使うラムダは参照キャプチャ・非ローカルは値キャプチャ(F.52〜F.53)、`this` と `[=]` を混ぜない(F.54)、`va_arg` を使わない(F.55)、早期 return でネストを避ける(F.56)。

### クラス(C)
- C.1〜C.9: 関連するデータをまとめる、不変条件があるなら `class`・メンバーが独立に変わるなら `struct`、メンバー関数は内部表現が必要なものだけ、ヘルパーは同じ名前空間に、公開を最小限に、非 public のメンバーがあれば `class`、型定義と変数宣言を1文にまとめない。
- C.10〜C.13: 具象型を優先する、regular にする、コピー/ムーブ可能な型に const メンバーや参照メンバーを持たせない、依存関係の順にメンバーを宣言する。
- 既定の操作: C.20 ゼロの規則、C.21 コピー/ムーブ/デストラクターは一緒に定義または削除する、C.22 意味を一貫させる。デストラクター C.30〜C.37: 必要なときだけ定義する、全リソースを解放する、所有する生メンバーに注意する、基底クラスのデストラクターは `public virtual` か `protected` 非 virtual、失敗させない、`noexcept`。
- コンストラクター C.40〜C.52: 不変条件があればコンストラクターを定義する、完全に初期化されたオブジェクトを作る、有効なオブジェクトを作れないなら例外、コピー可能なクラスには既定コンストラクター、既定コンストラクターは単純で例外を投げない、既定のメンバー初期化子、単一引数コンストラクターは `explicit`、宣言順に初期化する、代入より初期化、初期化中に仮想動作が必要ならファクトリ、委譲コンストラクターと継承コンストラクター。
- コピー/ムーブ C.60〜C.67: 非 virtual の `operator=` は `const&` / `&&` を受け取り `&` を返す、コピーはコピーする・ムーブはムーブして元を有効な状態に残す、自己代入に安全にする、ムーブ操作は `noexcept`、ポリモーフィックなクラスは public のコピー/ムーブを抑止する。その他 C.80〜C.90: `=default` / `=delete` を明示する、コンストラクターとデストラクターで仮想関数を呼ばない(C.82)、`noexcept` の `swap`(C.83〜C.85)、対称で `noexcept` な `==`(C.86)、基底クラスの `==` に注意(C.87)、`noexcept` なハッシュ(C.89)、trivially copyable でない型に `memset` / `memcpy` を使わない(C.90)。
- コンテナー C.100〜C.109: STL に従う、値セマンティクス、ムーブ操作、initializer_list コンストラクター、空になる既定コンストラクター、ポインターのようなハンドルには `*` と `->`。
- 階層 C.120〜C.153: 本質的に階層的な概念にだけ階層を使う、インターフェースはデータを持たない純粋抽象クラス、`virtual` / `override` / `final` のどれか1つだけ(C.128)、インターフェース継承と実装継承を区別する、自明な getter/setter・不要な `virtual`・`protected` データ・アクセスレベルの混在を避ける(C.131〜C.134)、`final` は控えめに(C.139)、オーバーライドで既定引数を変えない(C.140)、スライシングを避けるためポリモーフィックなオブジェクトはポインターか参照で扱う(C.145)、階層をたどるのが避けられないときだけ `dynamic_cast`(C.146〜C.148)、裸の `new` / `delete` を使わない(C.149〜C.151)、派生クラスの配列を基底ポインターに変換しない(C.152)、キャストより仮想関数呼び出し(C.153)。
- オーバーロード C.160〜C.170: 演算子は慣習的な意味に保つ、対称な演算子は非メンバー、ほぼ同等の操作にだけオーバーロード、暗黙の変換演算子を避ける、`swap` のようなカスタマイズポイントには `using` 宣言、演算子は被演算子の名前空間に定義する。共用体 C.180〜C.183: 同時に使われない選択肢のメモリ節約のためだけ、`variant` かタグ付き共用体を優先、型パンニングに使わない。

### 列挙型とリソース(Enum、R)
- Enum.1〜Enum.8: マクロより列挙型、`enum class`、列挙型に操作を定義する、列挙子を `ALL_CAPS` にしない、無名列挙型を避ける、基底型と値は必要なときだけ指定する。
- R.1〜R.6: すべてのリソースを RAII で、生ポインターと参照は所有しない、インターフェースの生ポインターは単一オブジェクトだけ(配列は `span`)、スコープ付きオブジェクトを優先、非 const のグローバルを避ける。R.10〜R.15: `malloc` / `free` を使わない、明示的な `new` / `delete` を使わない、確保したらすぐ管理オブジェクトに渡す、1文で確保は1回だけ、`[]` 引数を使わない、確保と解放のオーバーロードは対にする。
- スマートポインター R.20〜R.37: `unique_ptr` / `shared_ptr` で所有権を表す、`unique_ptr` を優先、`make_shared` / `make_unique`、循環は `weak_ptr` で断つ、スマートポインターを引数にするのは寿命のセマンティクスを表すときだけ(所有権を取得・共有するなら値渡し、付け替えるなら `&`)、エイリアスされたスマートポインターから得たポインターや参照を渡さない。

### 式と文(ES)
- 宣言 ES.1〜ES.12: 標準ライブラリと適切な抽象化を優先する、重複を避ける、スコープは小さく、`for` / `if` の初期化部で宣言する、ローカル名は短く・非ローカル名は長く、似た名前や(マクロ以外の)`ALL_CAPS` を避ける、1つの宣言で1つの名前、型名の繰り返しを避けるため `auto`、入れ子のスコープで名前を再利用しない。
- 初期化 ES.20〜ES.28: 必ず初期化する、使う直前に、値があるときだけ宣言する、`{}` を優先する、所有ポインターは `unique_ptr`、既定で `const` / `constexpr`、1つの変数に1つの目的、スタック上の C 配列の代わりに `std::array`、複雑な初期化にはラムダ。
- マクロと式 ES.30〜ES.34、ES.40〜ES.50: 定数や関数にマクロを使わない、やむを得ないなら一意の `ALL_CAPS` 名、C の可変長引数を使わない、複雑な式を避け迷ったら括弧、ポインターは単純に(`span` を優先)、評価順序が未定義の式を書かない、マジックナンバーを使わない、情報を失う変換をしない、`nullptr`、キャストを避け名前付きキャストを使い const を外さない。
- ES.55〜ES.65: 範囲チェックが不要になるようにする、`std::move` は別のスコープに渡すときだけ、裸の `new` / `delete` を使わない、配列は `delete[]`、別の配列へのポインターを比較しない、スライスしない、`T{e}` を使う、無効なポインターを参照外ししない。
- 文 ES.70〜ES.87: 定数との比較が連なるなら `if` の連鎖より `switch`、シーケンスには範囲 `for`、明らかなループ変数があれば `for`・なければ `while`、`do`・`goto`・多用する `break` / `continue` を避ける、暗黙のフォールスルーをしない(`[[fallthrough]]`)、`default` は共通のケースだけ、名前のないガードオブジェクトを書かない(ES.84)、空文は目に見える形に、本体でループ変数を変更しない、冗長な `== true` / `!= nullptr` を書かない。
- 算術 ES.100〜ES.107: 符号付きと符号なしを混ぜない、符号なしはビット操作だけ、算術は符号付き、オーバーフロー・アンダーフロー・整数のゼロ除算をしない、負の値を避ける目的や添字に `unsigned` を使わない(`gsl::index` を使う)。

### 性能・並行処理・エラー・定数(Per、CP、E、Con)
- Per.1〜Per.7: 理由なく、早すぎる段階で、性能が重要でないコードを最適化しない、複雑なコードや低レベルのコードが自動的に速いわけではない、測定する、後から最適化できるインターフェースにする。Per.10〜Per.19: 型システムに頼る、コンパイル時に計算する(`constexpr`)、コンパクトなデータと予測しやすいメモリアクセスが最も重要。Per.12〜Per.15、Per.17、Per.30 は原典で空。
- CP.1〜CP.9: マルチスレッドで実行される前提で書く、データ競合を起こさない、書き込み可能な共有データを最小化する、タスクで考える、同期に `volatile` を使わない、ツールで検証する。CP.20〜CP.26: ロックは RAII だけ、複数の mutex は一括取得する(`scoped_lock`)、ロック中に未知のコードを呼ばない、`jthread` を優先、`detach()` しない。CP.31〜CP.32、CP.40〜CP.44: 小さなデータは値渡し、無関係なスレッド間では `shared_ptr`、コンテキストスイッチ・スレッドの生成・クリティカルセクションを最小化する、条件変数の待機には条件が必要、ロックオブジェクトに名前を付ける。CP.50〜CP.53: mutex は保護するデータと一緒に定義する、キャプチャ付きラムダをコルーチンにしない、中断点をまたいでロックを保持しない、コルーチンの引数は値渡し。CP.60〜CP.61: タスクの結果には `future` / `async()`。CP.100〜CP.111、CP.200: 必要でない限りロックフリーを避ける、手書きのダブルチェックドロッキングをしない(`call_once`、関数内 static)、`volatile` は C++ 外のメモリにだけ。
- E.1〜E.8: エラー戦略を早めに設計する、仕事を果たせないときは例外を投げる、例外はエラーだけに使う、コンストラクターが不変条件を確立する、RAII でリークを防ぐ、事前条件・事後条件を明記する。E.12〜E.19: 例外で抜けることが不可能なら `noexcept`、リソースを直接所有している間は投げない、ユーザー定義型を値で投げ参照で捕まえる、デストラクター・解放・`swap` は失敗させない、あらゆる所ですべてを catch しない、明示的な `try` / `catch` を最小化する、ハンドルがない後始末には `final_action`。E.25〜E.28: 例外を使わない場合は、RAII を模倣する・早く失敗させる・エラーコードを体系的に使う・グローバルなエラー状態を避ける。E.30〜E.31: 例外指定を使わない、`catch` 節の順序を正しくする。
- Con.1〜Con.5: オブジェクトは既定で不変、メンバー関数は観測可能な状態を変えない限り `const`、ポインターと参照は既定で `const`、構築後に変わらないオブジェクトは `const`、コンパイル時に決まる値は `constexpr`。

### テンプレート・C・ソースファイル・ライブラリ(T、CPL、SF、SL)
- T.1〜T.5、T.10〜T.13: テンプレートで抽象度を上げる、すべてのテンプレート引数をコンセプトで制約する(標準のコンセプトと、`auto` よりコンセプト名を優先)。T.20〜T.26: コンセプトには意味、完全な操作の集合、公理、使用パターンによる定義が必要、相補的な制約を避ける。T.40〜T.49: アルゴリズムの操作には関数オブジェクト、本質的な性質だけを要求する、エイリアステンプレート、`typedef` より `using`、目立つ無制約のテンプレートと型消去は可能な限り避ける。T.60〜T.69: コンテキスト依存を最小化する、依存しないメンバーは非テンプレートの基底クラスに置く、別の実装には特殊化またはタグディスパッチ、`()` より `{}`、カスタマイズポイントのつもりでない限り修飾なしの呼び出しをしない。T.80〜T.84: 階層を安易にテンプレート化しない、階層と配列を混ぜない、メンバーテンプレートを virtual にしない、安定した ABI のために非テンプレートのコア実装。T.100〜T.103: C の可変長引数の代わりに可変長テンプレート、同種のリストには `initializer_list`。T.120〜T.125: テンプレートメタプログラミングは必要なときだけ、標準の機能を優先する。T.140〜T.150: 再利用できる操作に名前を付ける、関数テンプレートは特殊化せずオーバーロードする、`static_assert` でコンセプトを確認する。T.4、T.67、T.101〜T.102 は原典で本文がない。
- CPL.1〜CPL.3: C より C++ を優先する、C が必要なら C と C++ の共通部分を使い C++ としてコンパイルする、C のインターフェースは C++ から呼ぶ。
- SF.1〜SF.13: コードは `.cpp`・インターフェースは `.h`、ヘッダにオブジェクトや非 inline 関数の定義を置かない、共有する宣言はすべてヘッダに、`.cpp` は自分のヘッダを最初に include する、`using namespace` は移行・基盤ライブラリ・ローカルスコープだけでヘッダのグローバルスコープでは使わない、一意なインクルードガード、循環依存を避ける、間接的な include に頼らない、自己完結したヘッダ、相対パスには引用符・それ以外は山括弧、移植性のあるヘッダ名。SF.20 は原典で空。SF.21〜SF.22: ヘッダに無名名前空間を置かない、内部のエンティティには無名名前空間。
- SL.1〜SL.4: ライブラリを使う、標準ライブラリを優先する、`std` に何も足さない、型安全に使う。SL.con.1〜SL.con.4: C 配列より `array` / `vector`、既定は `vector`、境界エラーを避ける、trivially copyable でない型に `memset` / `memcpy` を使わない。SL.str.1〜SL.str.12: `std::string` が所有し `string_view` / `span<char>` が参照する、C 文字列には `zstring`、`char*` は1文字を指すときだけ、生のバイトには `std::byte`、文字列リテラルには `s` サフィックス。SL.io.1〜SL.io.50: 文字単位の入力は必要なときだけ、不正な入力を考慮する、iostream を優先、`printf` を使わない限り `sync_with_stdio(false)`、`endl` を使わない。SL.C.1: `setjmp` / `longjmp` を使わない。読んだ範囲では、SL.regex と SL.chrono の下にルールはなかった。

### アーキテクチャ・非ルール・プロファイル(A、NR、Pro)
- A.1、A.2、A.4: 安定したコードと不安定なコードを分ける、再利用できる部分をライブラリにする、ライブラリ間に循環を作らない。
- NR.1〜NR.7 は非ルール(俗説): 宣言を関数の先頭にまとめる、`return` を1つにする、例外を避ける、1ファイルに1クラス、二段階初期化、`goto exit` による後始末、`protected` データ — を強制しない。
- プロファイル: Type.1〜Type.8(キャストを避ける、`static_cast` でダウンキャストしない、const を外さない、C スタイルのキャストを使わない、すべて初期化する、裸の共用体を避ける、可変長引数を避ける)、Bounds.1〜Bounds.4(ポインター演算をしない、添字は定数式だけ、配列からポインターへの減衰を避ける、チェックのないライブラリ機能を使わない)、Lifetime.1(無効かもしれないポインターを参照外ししない)。

### 命名とレイアウト(NL)
- NL.1〜NL.3: コードで言えることをコメントに書かない、意図をコメントする、コメントは簡潔に。NL.4: インデントを一貫させる。NL.5: 名前に型情報を入れない。NL.7: 名前の長さはスコープの広さに見合わせる。NL.8: 命名スタイルを統一する。NL.9: `ALL_CAPS` はマクロだけ。NL.10: `underscore_style` を優先する。NL.11: リテラルを読みやすくする(桁区切り、サフィックス)。
- NL.15〜NL.21: 空白は控えめに、クラスメンバーの順序は 型・コンストラクター/デストラクター・関数・データ、アクセスは `public` → `protected` → `private`、K&R 由来のレイアウト、`T& operator[]` のような宣言子の配置、読み間違えやすい名前を避ける、1行に1文、1つの宣言で1つの名前。NL.25〜NL.27: `f(void)` ではなく `f()`、`int const` ではなく `const int`、特に指定がなければ実装は `.cpp`・インターフェースは `.h`。NL.6、NL.12〜NL.14、NL.22〜NL.24、NL.28〜NL.30 は、読んだ範囲に存在しなかった。

### 要約していないもの
GSL(サポートライブラリの説明)、FAQ、付録 A〜D(ライブラリ、コードのモダナイズ、議論、支援ツール)、用語集、To-do には、番号付きのルールがない。

## プロジェクトルール: コメントとファイルヘッダー

これらのプロジェクトルールは、汎用的な ECC の記述や、上のソース規約と食い違う場合に、それらより優先します。Unreal Engine のコードでは、`.claude/rules/unreal-engine/coding-style.md` がこの節に規則を追加します。

### ファイルヘッダー(Doxygen)
新しい C++ のソースファイルとヘッダーファイルは、`#include` や `#pragma once` より前に、次のブロックで始めます。

```cpp
/**
 * @file PlayerController.cpp
 * @brief Handles player input and movement.
 * @date 2026-11-15
 * @author <output of `git config user.name`>
 */
```

- `@file`: 拡張子付きのファイル名(名前が一意でない場合、Doxygen はパスの一部も受け付ける)。
- `@brief`: ファイルの内容を説明する1文。
- `@date`: `YYYY-MM-DD` 形式の作成日。ファイルの作成時に1回だけ書き、更新しない(履歴は git が持つ)。
- `@author`: `git config user.name` の値。Claude が作るファイルでも同じ。
- 対象外: 生成されたファイルとサードパーティのコード。既存のファイルは、依頼がない限り後から追加しない。
- Doxygen のマニュアルより: コマンドは `\` または `@` で始まる。`\file` は、コメントブロックがそのファイルのドキュメントであることを示す。`/** */` と `///` のブロックが使える。ファイルのブロックが先頭になければならないとは、マニュアルに書かれていない。

### コメントのスタイル(C# のルールと同じ)
- 短い説明には `//` を使う。説明に複数行の `/* */` は使わず、`//` の行を続ける。`/** */` と `///` は、Doxygen のドキュメントブロックにだけ使う。
- 公開された宣言には、Doxygen のコメントでドキュメントを付ける。
- コメントは独立した行に書き、コードの行末には書かない。
- 文は大文字で始め、`//` の後に空白を1つ入れる。

### ピリオドの規則
すべてのコメント行の末尾にピリオド(`.`)を付ける。折り返したコメントの各行も含む。ピリオドが収まるように、各行を完結した文または句として書く。ピリオドを付けると内容が壊れる場合は例外とする: `@file`・`@date`・`@author` の行の値、必須の著作権表示、URL、コード例の中の行。区切りだけの行(`/**`、` */`)はコメントのテキストではない。

## プロジェクトルール: 初期化

このプロジェクトルールは、ECC の汎用の記述と、上の Core Guidelines の節と食い違うときは、それらに優先する(ES.23 はすべての初期化に `{}` を好むが、このプロジェクトは既定値にだけ `{}` を使う)。Unreal Engine のコードにも、`.claude/rules/unreal-engine/coding-style.md` の経由で適用する。

- 必ず初期化する(ES.20)。その型の既定値(0、`false`、`nullptr`、既定構築したオブジェクト)にする変数は、空のブレース `{}` で初期化する。初期化しないままにせず、`= 0`、`= false`、`= nullptr` とも書かない。
- それ以外の値にする変数は、`=` で初期化する。値を入れたブレース(`Count{5}`)は使わない。
- 既定のメンバ初期化子、ローカル変数、名前空間スコープの変数に適用する。

```cpp
int Count{};
bool bReady{};
Foo* Target{};
int Limit = 5;
float Speed = 600.0f;
```

- 未確認: このルールと、縮小変換の検査や `auto` との関係(`auto X = 5;` は書けるが、`auto X{};` は書けない)。
