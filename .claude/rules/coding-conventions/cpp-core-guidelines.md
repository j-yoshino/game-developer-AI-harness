# C++ コーディング規約(C++ Core Guidelines)

- 出典: https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines (2026-11-15 取得)
- 位置づけ: ISO C++ の Bjarne Stroustrup と Herb Sutter らによる、現代的な C++ のガイドライン。
- 要約であり原文の転載ではない。ルール ID は原文の ID。

- **Unreal Engine のプロジェクト(`Source/**/*.{h,cpp}`)では `unreal-cpp.md` を優先**する。両方が読み込まれるのは、`paths` で除外指定ができないため。

## 基本理念(P)

- 意図はコメントではなくコードで表す(P.1)。標準 ISO C++ で書き、拡張機能は局所化する(P.2)。
- 静的な型安全を目指す(P.4)。実行時チェックよりコンパイル時チェックを優先し(P.5)、実行時エラーはできるだけ早く検出する(P.7)。
- リソースを漏らさない(P.8)。可変データより不変データを好む(P.10)。
- 雑で低レベルな構文はカプセル化する(P.11)。静的解析などのツールを使い(P.12)、適切なライブラリを使う(P.13)。

## 関数(F)

- 関数は1つの論理操作だけを行い(F.2)、短く保つ(F.3)。出力引数が複数あるなら、戻り値(名前付き `struct` など)を使う(F.2、F.20、F.21)。
- 引数の渡し方(F.15〜F.21):
  - 安価にコピーできる型は値渡し、それ以外の入力は `const&`(F.16)。
  - 入出力引数は非 `const` 参照(F.17)。持ち去る引数は `X&&` + `std::move`(F.18)。転送は `TP&&` + `std::forward`(F.19)。
- 所有権が不要なら `T*` / `T&` を受け取り、特定のスマートポインタを強制しない(F.7)。「引数なし」が有効なら `T*`、そうでなければ `T&`(F.60)。
- ローカルオブジェクトへのポインタや参照を返さない(F.43)。`return std::move(local)` は書かない(F.48)。`const` 値を返さない(F.49)。
- ラムダ: ローカルで使うなら参照キャプチャ、非ローカル(返す・保存する・別スレッドに渡す)なら値キャプチャ(F.52、F.53)。`[=]` と `this` を混ぜず、`this` は明示する(F.54)。
- 例外を投げない関数には `noexcept`(F.6)。可変長引数 `va_arg` を使わない(F.55)。例外的な場合は早期 `return` で条件のネストを浅くする(F.56)。

## クラス(C)

- 不変条件があるなら `class`、公開データだけなら `struct`(C.2、C.8)。
- **ゼロの規則**: 既定の特殊メンバー関数で済むなら自分で定義しない(C.20)。コピー・移動・デストラクターのどれかを定義・削除したら、全部を明示する(C.21)。
- コンストラクターは不変条件を確立し、全メンバーを初期化する(C.40、C.41)。有効なオブジェクトを作れないなら例外を投げる(C.42)。単一引数のコンストラクターは原則 `explicit`(C.46)。
- デストラクターは `noexcept`、失敗させない(C.36、C.37)。基底クラスのデストラクターは「`public` かつ `virtual`」か「`protected` かつ非 `virtual`」(C.35)。
- コンストラクターとデストラクターの中で仮想関数を呼ばない(C.82)。ムーブ操作は `noexcept`(C.66)。自己代入に安全にする(C.62、C.65)。
- 階層は、本質的に階層構造を持つ概念にだけ使う(C.120)。`virtual` / `override` / `final` は1つだけ付ける(C.128)。`protected` データを避ける(C.133)。
- 多相オブジェクトはポインタか参照で扱い、値渡しでスライスしない(C.145)。`dynamic_cast` は、仮想関数で置き換えられないときだけ(C.146)。
- 演算子は従来の意味に合わせて定義する(C.160)。暗黙変換演算子は避ける(C.164)。型パンニングに `union` を使わない(C.183)。

## 列挙型(Enum)

- マクロで定数を定義せず、`enum` か `constexpr` を使う(Enum.1)。素の `enum` より **`enum class`** を優先する(Enum.3)。列挙子を `ALL_CAPS` にしない(Enum.5)。

## リソース管理(R)

- 資源は RAII で管理し、手動の解放に頼らない(R.1)。
- 生ポインタは所有権を持たないものとして扱う(R.3)。所有権は `unique_ptr` / `shared_ptr` で表し(R.20)、共有が不要なら `unique_ptr` を優先する(R.21)。作るときは `make_unique` / `make_shared`(R.22、R.23)。
- `malloc` / `free` を避ける(R.10)。`new` / `delete` を直接書かない(R.11)。

## 式と文(ES)

- 変数は使う直前に宣言し(ES.21)、必ず初期化する(ES.20)。スコープは小さく(ES.5)。1つの宣言では1つの名前だけ(ES.10)。入れ子のスコープで名前を再利用しない(ES.12)。
- 初期化は `{}` を優先する(ES.23)。変更しない変数は `const` / `constexpr`(ES.25)。複雑な初期化はラムダで包んで `const` にする(ES.28)。
- マクロより `constexpr` やテンプレート(ES.30、ES.31)。マジックナンバーは名前付き定数にする(ES.45)。`nullptr` を使い、`0` / `NULL` を使わない(ES.47)。
- キャストは極力避け(ES.48)、必要なら名前付きキャスト(ES.49)。`const_cast` で `const` を外さない(ES.50)。
- 符号付きと符号なしを混ぜない(ES.100)。通常の算術は符号付き(ES.102)。添字には `unsigned` ではなく `gsl::index`(ES.107)。
- `switch` の暗黙のフォールスルーを避け、意図するなら `[[fallthrough]]`(ES.78)。名前のないロック変数を書かない(ES.84)。`goto` を避ける(ES.76)。

## 性能(Per)

- 早すぎる最適化をせず(Per.2)、計測なしに性能の主張をしない(Per.6)。計算できるものはコンパイル時に移す(Per.11)。メモリへは隣接データを順にアクセスする(Per.19)。

## 並行処理(CP)

- データ競合を起こさない(CP.2)。書き込み可能なデータの共有を減らす(CP.3)。スレッドではなくタスクで設計する(CP.4)。`volatile` を同期に使わない(CP.8)。
- `lock()` / `unlock()` を直接呼ばず RAII のロックを使う(CP.20)。複数の mutex は `scoped_lock` などで一括取得する(CP.21)。ロック中に未知のコードを呼ばない(CP.22)。`detach()` を使わない(CP.26)。
- コルーチン: キャプチャ付きラムダをコルーチンにしない(CP.51)。`co_await` をまたいでロックを保持しない(CP.52)。引数は値渡し(CP.53)。

## エラー処理(E)と定数(Con)

- 仕事を果たせないときは例外で知らせる(E.2)。例外はエラー処理にだけ使う(E.3)。コンストラクターで不変条件を確立できなければ例外(E.5)。リソースは RAII で守る(E.6)。
- 例外は値で投げ、参照(通常は `const&`)で捕まえる(E.15)。デストラクター・メモリ解放・`swap` は失敗させない(E.16)。
- オブジェクトは基本的に `const` にする(Con.1)。状態を変えないメンバー関数は `const`(Con.2)。コンパイル時に決まる値は `constexpr`(Con.5)。

## テンプレート(T)・ソースファイル(SF)・標準ライブラリ(SL)

- 型引数には概念(concept)を指定し、要求する操作を最小限にする(T 章)。
- ヘッダには宣言だけを置き、インライン関数とテンプレートは例外(SF.1〜)。include ガードを付け、ヘッダは単独でコンパイルできるようにする。ヘッダのグローバルスコープで `using namespace` を書かない。
- 可能な限り標準ライブラリを優先する(SL.1、SL.2)。`std` 名前空間に独自のものを足さない(SL.3)。

## 命名とレイアウト(NL。読めた範囲)

- コメントは意図を書く(NL.1、NL.2)。インデントを一貫させる(NL.4)。名前に型情報を埋め込まない(NL.5)。名前の長さはスコープに見合わせる(NL.7)。
- 命名スタイルを統一する(NL.8)。`ALL_CAPS` はマクロだけ(NL.9)。**単語の区切りは `underscore_style` を優先する**(NL.10)。
- 空白は控えめに(NL.15)。メンバー宣言順は、型・コンストラクター等・関数・データ、アクセスは `public` → `protected` → `private`(NL.16)。**K&R 系のレイアウト**(NL.17)。
- 1行に文を2つ以上書かない(NL.20)。1つの宣言では名前を1つ(NL.21)。引数の型に `void` を使わない(NL.25)。`const` は `const int` の位置(NL.26)。拡張子は実装 `.cpp`、インターフェース `.h`(NL.27)。
