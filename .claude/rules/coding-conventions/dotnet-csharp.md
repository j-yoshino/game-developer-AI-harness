## 言語ガイドライン

- 新しい C# の機能とバージョンを使い、古い構文を避ける。
- 処理できる例外だけを `catch` する。`Exception` を例外フィルターなしで捕まえない。具体的な例外型で意味のあるメッセージを出す。
- コレクション操作は LINQ、I/O は `async` / `await`。デッドロックに注意し、必要なら `ConfigureAwait` を使う。
- 型は言語キーワードを使う(`System.String` ではなく `string`、`System.Int32` ではなく `int`)。
- 整数は通常 `int`。`unsigned` は、その型固有の理由があるときだけ。
- `var` は、右辺から型が読み手に明らかなときだけ使う(`new`、明示キャスト、リテラル代入)。メソッド名から型が明らかだと見なさない。変数名で型を表さず、型は型で示し、変数名は意味を表す。
  - `for` のループ変数は `var` でよい。`foreach` のループ変数は型を明示する。
  - LINQ のクエリ結果は `var` でよい(匿名型や入れ子のジェネリック型になるため)。
  - `dynamic` は実行時の型推論が必要なときだけ使い、`var` の代わりにしない。
- 明確さと単純さを優先し、過度に複雑なロジックを避ける。

### 文字列・初期化・コレクション

- 短い連結は文字列補間 `$"..."`。位置指定ではなく式ベースの補間を使う。
- ループ内で文字列を足すときは `StringBuilder`。
- エスケープや逐語的文字列より、生文字列リテラル `"""` を使う。
- `record` のプライマリコンストラクターの引数は **PascalCase**、`class` / `struct` のプライマリコンストラクターの引数は **camelCase**。
- プロパティの初期化を強制したいときは、コンストラクターではなく `required` プロパティ。
- コレクションの初期化はコレクション式 `[ ... ]`。

### デリゲート・例外・リソース

- デリゲート型を自分で定義するより `Func<>` / `Action<>` を使う。デリゲートのインスタンス化は短縮構文。
- `using` で足りる `try-finally`(`finally` が `Dispose` だけ)は `using` に置き換える。波かっこ不要の `using` 宣言を使う。
- 後で解除しないイベントハンドラーはラムダ式。
- 静的メンバーは、宣言したクラス名で呼ぶ。派生クラス名経由で呼ばない。

### オブジェクト生成・LINQ・名前空間

- 変数の型とオブジェクトの型が一致するなら、`var x = new X();` または `X x = new();` を使い、オブジェクト初期化子を活用する。
- LINQ: クエリ変数には意味のある名前を付ける。匿名型のプロパティ名は PascalCase。曖昧になるプロパティ名は付け替える。`where` を他の句より先に置く。内側のコレクションには複数の `from` を使い、`join` を避ける。
- ファイルスコープの名前空間 `namespace X;` を使う。`using` は名前空間宣言の**外**に置く。

## スタイル

- インデントは**スペース4つ**、タブ不可。括弧は **Allman**(開き・閉じとも独立した行)。
- 1行に1ステートメント、1宣言。メソッドとプロパティの定義の間は1行以上空ける。
- 式の優先順位が紛らわしいときは括弧で明示する。長いステートメントは分割し、2項演算子の前で改行する。
- コメント: 短い説明は `//`、複数行 `/* */` は避ける。公開メンバーには XML ドキュメントコメント。コメントは行末ではなく別の行に書き、大文字で始めてピリオドで終え、`//` の後に空白を1つ入れる。
- 行長 65 文字の制限は、原文では docs の表示用。**本プロジェクトでは適用しない**(判断)。

## 命名

- 原文のこの記事には、クラス・メソッド・フィールドなどの一般的な命名規則の節が**ない**。確認できた命名は上記のプライマリコンストラクターの引数だけ。
