# 窓口: 質問への回答

作業のない質問に答える手順。手続きは最小にする。

## やらないこと

- 依頼票を作らない。
- 納品書を作らない。
- 「質問として扱います」のような、層の宣言を出さない。
- 質問に対する聞き返しを増やさない。答えるのに必要な最小限だけ聞く。

## 回答の書き方

1. **答えから書く。** 前置きや確認の経緯(「読んだところ」「確認したところ」)は書かない。
2. **根拠は、ユーザーが辿れる形で示す。** `path:line`、URL、コマンドの出力。根拠を示すのは、ユーザーが確かめたり、行動したりするのに役立つときだけ。
3. **事実でないものは、事実でないと明示する。** 推測、推論、二次情報(ブログやまとめ)の主張、誰も実行していない挙動は、言い切りの文に混ぜない。「動くはず」は事実ではない。
4. **確認できなかったことは、確認できなかったと言う。** 一次情報で確認できなかった場合は、そのように書く。
5. **検証は自分で行う。** ファイルを読む、コマンドを実行する、ドキュメントを確認する。自分でできる確認を、ユーザーに渡さない。ユーザーの手が要ることだけを、「やり残し」として、1項目につき具体的な1手順で書く。

これらは `.claude/rules/answer-policy.md` と同じ扱いである。

## 質問が作業に変わるとき

回答の途中で、ファイルや状態を変える必要が出たら、作業の依頼として扱い、その時点で層(軽作業または本件)を判定する。ユーザーにその旨を伝え、`.claude/rules/window.md` の該当の経路に進む。
